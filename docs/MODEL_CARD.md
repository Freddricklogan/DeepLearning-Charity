# Model card — charity funding outcome classifier

Generated by `charity-model report --seed 42`; every number below was measured in that run.

## Model details
- Task: binary classification of `IS_SUCCESSFUL` (funding used effectively) from application features.
- Architecture: multilayer perceptron, hidden layers 80 → 30 (ReLU, batch normalisation, dropout 0.2), sigmoid output; 6,421 parameters; Keras 3 on the JAX backend.
- Training: Adam (lr 0.001), batch 256, up to 30 epochs with early stopping (patience 5) on validation loss, best weights restored; stopped after 30 epochs, best at epoch 29.
- Baseline: L2-regularised logistic regression on the same features.

## Data
- Alphabet Soup charity applications (34,299 rows) as distributed with the Deep Learning bootcamp exercise; vendored in data/charity_data.csv.gz.
- 34,299 rows; identifiers EIN and NAME dropped; rare categories folded into Other (APPLICATION_TYPE: 9 values; CLASSIFICATION: 66 values); ASK_AMT log-transformed; one-hot encoding → 43 features.
- Stratified 75/25 split (seed 42); scaler fitted on the training rows only. Test rows: 8,575; positive rate 0.5324.

## Intended use and limits
- A teaching example of an honest tabular-classification pipeline. Not a decision system: the features describe applications, not outcomes, and the label's provenance is the exercise's, not audited.
- The network's advantage over logistic regression is +0.50 accuracy points on this split; treat differences of that size as within run-to-run variation unless repeated across seeds.
- No fairness analysis is possible: the dataset carries no protected attributes, and none should be inferred from organisation names.
